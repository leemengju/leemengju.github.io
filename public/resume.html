專案

總勝分報表資料庫遷移（MySQL → ClickHouse）
  • 背景：總勝分報表查 MySQL 月／日分表，玩家整月查詢約 104 秒。
  • 專案內容：遷移至 ClickHouse（MV + AggregatingMergeTree），依日期在 CH／MySQL 間分流。
  • 專案挑戰：零停機切換、遷移前後資料一致性驗證。
  • 貢獻與成果：獨立主導遷移、CH schema 與分區鍵設計、以實資料對數；整月查詢 約 104s → 約 5s（約 21×），零停機。
區間賠率監控 + 運營資料 LINE／Slack 機器人自動推送
  • 背景：風管每日人工整理區間賠率與運營資料並回報，耗時且易漏。
  • 專案內容：以 LINE／Slack Bot SDK + cloudflared 內網穿透，將監控結果定時自動推送。
  • 專案挑戰：防火牆內網限制、跨機時鐘偏移造成的資料競態。
  • 貢獻與成果：獨立打通內網穿透、設計推送排程與異常處理；人工回報 → 全自動推送，約省 304 小時／年。
玩家金流異動統計報表
  • 背景：客服／風管需查詢玩家金流異動，原查詢跨月分表，20 人批量查詢需 4~5 分鐘。
  • 專案內容：重構查詢邏輯，依搜尋日期自動分流 ClickHouse 單表／MySQL 分表，並封裝查詢建構器。
  • 專案挑戰：跨月分表查詢慢、批量查詢逾時、CH 與 MySQL 結果需完全對齊。
  • 貢獻與成果：獨立設計分流邏輯與 CH schema、以實資料對數驗證；20 人批量查詢 4~5 分鐘 → 15~20 秒（QA 實測約 3.2×）。
WSS 憑證隱形故障：根因定位與到期監控
  • 背景：IT 換完憑證未重啟服務，行程仍持有記憶體中的舊憑證；行程、埠、log 全綠，前端 wss 卻全掛，隔兩天才被發現。
  • 專案內容：以實際完成 TLS 握手取得「服務真正送出的憑證」，與磁碟憑證做 SHA256 指紋比對，掛進既有排程每週主動檢查。
  • 專案挑戰：憑證缺失會靜默降級為明文連線、埠仍在聽，只查行程與埠一律看不出來；告警須讓非工程人員也能照做。
  • 貢獻與成果：獨立定位根因並設計監控；偵測時點由故障後 2 天提前至到期前 14 天預警，5 種告警各附依主機動態產生的修復指令。
遊戲後台判斷式重構：巨型 switch 到 Handler 模式
  • 背景：勝分統計、角色輸贏、機台資訊等 7 支後端核心是上千行的巨型 if/elseif 與 switch（主檔 1059 行），所有遊戲共用、改 A 可能誤傷 B。
  • 專案內容：重構為 Handler 模式（Contract + Registry 單一分派點、約 45 個 handler），新增遊戲改為「加一個檔 + Registry 一行」。
  • 專案挑戰：這是財務／營運統計的寫入與讀取端，行為不得有任何改變，但程式碼沒有既有測試。
  • 貢獻與成果：主檔 1059 → 320 行、巨型共用模型檔累計卸下 1550+ 行；以 dispatch 等價、新舊並跑輸出全等、攔截實際 SQL 做位元組比對（492/492）證明行為零改變。
共用設定模組化重構
  • 背景：共用設定主檔長年是跨遊戲設定的「垃圾桶」，膨脹到 4221 行，改任一功能都要在 4000+ 行中翻找，多人並行常衝突。
  • 專案內容：分三波按職責拆為 10 檔（4 主模組 + 5 個 Dialog 元件 + 1 支邏輯 js），獨立路由由 1 條增為 4 條。
  • 專案挑戰：在業務持續擴充的前提下重構，且不得影響既有設定行為；需先以單一模組試水、驗證可行再放大。
  • 貢獻與成果：主檔 4221 → 1963 行（−54%）；新框架於半年後被全新貨幣機制後台直接沿用，拆分策略在當時還不存在的需求上得到事後驗證。
